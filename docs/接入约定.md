# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息。structured 按区域采集 FlatGeobuf 子集，必须提供闭合矩形 region `[minX,minY,maxX,maxY]`，缺失或形状非法返回 400。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 每个区域内设施一条，id 取设施属性，不使用候选节点下标。

## 结构化收件语义

structured 收件只沿 HTTP Range 读取来源字节，流程与证据如下：

1. 首次请求固定携带 `Range`，以 206 + `Content-Range` 确认远端支持范围读取；返回 200 整文件视为远端不理会 Range，登记 `range-ignored` 问题并降级为整文件缓冲上的扫描，state 为 partial，不会伪装成按范围领取。
2. 首个响应的 ETag 确定版本，之后每次读取都携带 `If-Match`；收到 412 或 ETag 变化立即停止，state 为 rejected，已读字节仍作为证据保留，不拼接出看似正常的数据。
3. header 的 `indexNodeSize>0` 时，先读取 packed Hilbert R-tree 索引节点，沿索引裁剪出候选要素（候选只代表包围盒相交），再逐个读取候选要素并按真实几何判断是否进入 region；`indexNodeSize=0` 时读取整个要素区完整扫描，issues 中以 `full-scan` 说明扫描方式。
4. 几何判断对 Point、LineString、Polygon、MultiPolygon 等承诺类型做真实相交：边界接触算相交，洞内（含洞边界接触）不算；仅包围盒相交的要素不进入 records。承诺范围外的几何类型登记 `unsupported-geometry`，保留原文且不计入结果。

records 每条含 `id`（设施属性 id）、`properties`、`geometry`、`hit`（命中几何依据，含是否边界接触）与 `locator`（来源要素序号、绝对字节偏移与长度，序号仅作定位，不作身份）。

coverage 记录 `strategy`（rtree-candidates+geometry-filter 或 full-scan:no-spatial-index，范围被忽略时带 range-ignored-full-buffer 后缀）、`indexPruned`、`rangeSupported`、`fullFileBuffered`、要素总数、检查候选数、命中数、请求次数、传输字节数与落盘字节数。evidence.requests 逐次记录 Range 头、If-Match、状态码、Content-Range、ETag、传输字节与响应摘要，evidence.blobs 以 SHA-256 关联 DATA_DIR/blobs 中的实际字节。
